一、坐标约定与实验目标

相机刚性安装在法兰，棋盘格固定在工作台。整个实验过程中不得改变相机安装、
棋盘格位置、相机焦距/分辨率/裁剪方式或相机内参。
用户确认的棋盘格：11 列 × 8 行内角点，格长 5 mm（0.005 m），共 88 个内角点。
这里指内角点，不是黑白方格数量；相邻极端内角点范围为 50 mm × 35 mm。
用直尺复核打印比例；棋盘格应平整、完整可见、有白边，角点不能过小或模糊。

矩阵 T_A_B 表示将 B 系坐标转换到 A 系：
T_world_board(i) = T_world_flange(q_i) × T_flange_camera × T_camera_board(i)
robot_pose 来自图像时间戳对应的 URDF world -> flange TF，不取 TCP 位姿。
当前 URDF 的 world -> base_link 为单位变换，所以 world 与基座重合。
若以后改变 world_to_base，报告将是 world 坐标；基座坐标需再乘 T_base_world。

棋盘格原点必须全程对应同一个物理内角点：
在白边靠近一个极端内角点的位置做笔迹标记，不要涂改角点。
每个姿态稳定后，在程序画面点击这个物理内角点，然后按 S。
程序会重排 88 个角点，将所选点设为原点；
+X 沿 11 列方向，+Y 沿 8 行方向，+Z 按右手定则。
红色 ORIGIN 应始终贴近同一物理标记。
点击确认5秒有效，画面明显移动/检测失败/每次采样后需重新确认。
普通棋盘格的角点起点可能翻转；PnP误差很小也不能证明原点一致。
新增点击确认需要人工正确辨认标记，并非自动识别笔迹。

本轮“补偿”重新估计刚性的 T_flange_camera（手眼外参）。
不修改 URDF 的连杆长度、关节零偏或机器人 DH 参数；若目标是机器人运动学参数标定，
还需设计另一套模型与可观测性实验，不能把手眼外参更新等同于机器人绝对精度修正。

三、启动相机与只读机器人反馈

终端1：相机（先 source 相机驱动实际所在工作区，如有独立相机工作区）
ros2 pkg prefix orbbec_camera
ros2 launch orbbec_camera gemini2.launch.py

若提示 Package not found，必须先安装/编译或 source 驱动；Tool/gemini2.launch.py
本身不是驱动。2026-09-23续验时，本工作区已有 Orbbec 驱动源码，加载
install/setup.bash 后 ros2 pkg prefix orbbec_camera 可解析；但当前执行环境
未暴露相机USB/视频设备，尚未验证出图。包可解析不能代替图像和CameraInfo检查。
确认提供彩色原始图像、对应分辨率的 CameraInfo 和 camera_link -> 彩色光学系 TF。
本脚本使用 raw + K + D；不要把 image_rect 配上 raw 畸变参数。

终端2：只读反馈，IP按实际配置
ros2 launch my_robot_calib_config teach_capture.launch.py robot_ip:=192.168.58.2

该 launch 发布六关节 /joint_states 和 URDF 机器人 TF，启动时不发送运动指令。
本轮只读节点只解析8081反馈帧中已经与示教器核对的六关节位置；
若控制器帧长度与旧完整状态结构不同，只提示一次并继续按实际帧长度安全收包。
本节点不发布旧的 /nonrt_state_data；如修改或重新编译了节点，须停止旧launch后重启，
且不要同时运行两个 /joint_states 发布者。
示教/拖动模式仍由示教器操作。采集时不要并行运行 circle_task.launch.py、
ros2_control 控制器、其他运动程序、假关节发布器或另一套相同机器人TF。

检查（可单独终端，持续命令 Ctrl+C 结束）：
ros2 topic echo /joint_states --once
ros2 topic hz /joint_states
ros2 run tf2_ros tf2_echo world flange
ros2 topic echo /camera/color/camera_info --once
ros2 topic hz /camera/color/image_raw
ros2 topic echo /camera/color/image_raw --once --field header.frame_id
ros2 run tf2_ros tf2_echo camera_link <上一条显示的彩色光学坐标系>

先将六关节数值与示教器对照，ROS为弧度，示教器通常为度。
单独改变一个关节时，相应 j1..j6 的变化方向、数量级应一致。
若状态帧版本不匹配或关节数据异常，先解决反馈问题再采样。
当前只读节点的关节时间戳是主机收到反馈的时间，非控制器曝光同步时间；
图像须使用兼容的ROS时间，程序的时间门槛不能消除网络/相机固定延迟。
静止后采样用于减轻这些延迟的影响。

四、采集45组新数据

终端3（在工作区根目录）：
python3 src/2025_12/eye_in_hand_collector_bz.py \
  --columns 11 --rows 8 --square-size 0.005 \
  --output src/2025_12/calib_data_bz/session01

session01 必须是新目录；已有目录会拒绝启动，避免覆盖。下一轮改成 session02。
不指定 --output 会生成按时间命名的新目录。
相机与机器人 frame/topic 不同可用 --help 查看参数覆盖。

每一组：
1. 通过示教器进入拖动模式并改变姿态。
2. 松手后等待稳定；若拖动模式下仍漂移，按设备正常操作退出拖动并保持静止。
3. 等约1–2秒，让完整棋盘格清晰可见，点击同一物理原点旁的极端内角点。
4. 图像窗口获得焦点后按小写 s。控制台显示“已保存”才算成功。
5. 改变姿态再采下一组；按小写 q 退出，每次成功采样已经落盘。

初始质量门槛：
- 图像年龄不超过1秒，不能为零时间戳或重复帧。
- 最近0.75秒窗口内至少5个观测，覆盖至少0.5秒，相邻数据间隔不超过0.25秒。
- 六关节各自变化范围不超过0.1度。
- 棋盘格PnP平移变化不超过5 mm，旋转变化不超过2度。
- 图像与最近关节反馈时间差不超过100 ms，并获取图像时间点法兰TF。
- 每张图像的PnP角点拟合RMSE默认不超过1像素（--max-pnp-rmse 可调整）。
- 若六关节均与某个已保存姿态相差不到0.5度，拒绝近重复样本。
这些值是初始采样门槛，不代表毫米级最终精度或硬件安全判定。
若频繁拒绝，应先检查可见角点大小、抖动、照明、畸变和反馈频率。

45组应覆盖不同距离、画面区域与绕至少两个轴的明显转动，
不要只平移或只绕一个轴转动。求解会拒绝旋转跨度不足20度或旋转轴退化的数据。
每组保持同一物理原点、完整棋盘格可见；不在手仍施力时记录。

输出：
session01/samples.json：数据清单（图像文件名、关节角、法兰TF、棋盘格PnP、88个角点、
                       物体点坐标、内参、图像时间戳、frame和质量指标）
session01/img_0001.png ...：与记录对应的原始图像
不再分别glob图片与pose文件，也不由当前目录决定数据存储位置。
旧 calib_data_bz/img_*.png + pose_*.npy 缺少同步与原点确认，不能自动视为合格新数据。

五、先评价未补偿误差并固定30/15划分

保留工作区根目录原始 T_cam_to_flange.npy，不要覆盖。
必须先确认它满足：
P_flange = T_flange_camera_optical × P_camera_optical
文件名不能保证矩阵方向。若是相机本体系外参，使用 --baseline-frame body；
若矩阵实际方向相反，明确追加 --baseline-invert。不能为了降低误差尝试各种方向后选最小值。

python3 src/2025_12/error.py \
  --data src/2025_12/calib_data_bz/session01/samples.json \
  --baseline T_cam_to_flange.npy --baseline-frame optical \
  --report src/2025_12/calib_data_bz/session01/baseline_report.json

程序要求恰好45组，使用种子42随机划分30组训练、15组验证。
在数据目录写出 training.json、validation.json、split.json。
split.json 保存数据、基准矩阵的内容指纹与样本索引；
后续修改数据、基准矩阵/方向、种子或划分会报错。
第一份 baseline_report.json 留作补偿前报告。

六、只用30组训练数据求解手眼外参

python3 src/2025_12/eye_in_hand_solve_bz.py \
  --input src/2025_12/calib_data_bz/session01/training.json \
  --result src/2025_12/calib_data_bz/session01/compensated.json

求解会验证训练集角色和数据指纹，拒绝直接输入全部45组或 validation.json。
比较Tsai、Park、Horaud、Andreff、Daniilidis，
仅在30组训练集内部做留一交叉验证来选算法，再用全部30组训练样本拟合。
打印的 training-only LOO 是内部选型误差，不是15组独立验证误差。
数值函数复用 04_find_best_calibration.py；本次入口始终是 eye_in_hand_solve_bz.py。

输出：
compensated.json：矩阵、棋盘格位姿、方法选择指标、训练来源指纹
compensated.npy：T_flange_camera_optical，单位米；与基准文件分开保存
需要离线查看修正后的URDF时，可在上述命令中追加：
  --output-urdf src/2025_12/calib_data_bz/session01/compensated.urdf
导出不自动替换机器人正在运行的模型。不要将其中相机内部TF与相机驱动重复发布。
棋盘格原点为选定的内角点，和旧 ArUco 中心不相同，旧板位姿不能直接拿来作真值。

七、使用同一15组验证集比较补偿前后

python3 src/2025_12/error.py \
  --data src/2025_12/calib_data_bz/session01/samples.json \
  --baseline T_cam_to_flange.npy --baseline-frame optical \
  --compensated src/2025_12/calib_data_bz/session01/compensated.json \
  --report src/2025_12/calib_data_bz/session01/comparison_report.json

棋盘格流程需传带训练来源的 compensated.json；不接受无来源的补偿.npy代替。
程序会确认补偿结果来自同一个冻结训练集。验证集不参与算法选择或拟合。
不要反复根据这15组验证结果调参/删点；若如此使用，它们就不再是独立验证，
应另采一组未使用的新姿态作为最终测试集。

报告包含：
- 平移 MAE、RMSE、最大误差（mm）及XYZ偏差/标准差；
- 旋转 RMSE、最大误差（度）；
- 88个角点的独立闭环重投影RMSE（像素）；
- 每个验证样本的误差与补偿改善比例（负数表示变差）。

没有外部真值时，各个候选手眼矩阵用30组训练数据估计其固定棋盘格参考位姿，
再把15组观测与这个训练参考比较。因此报告衡量跨姿态一致性，
不能检测全部共同固定偏差，不能据此宣称机器人“绝对精度2 mm”或满足某项抓取需求。

闭环像素误差使用：
T_camera_board_pred = inverse(T_world_flange × T_flange_camera) × T_world_board_reference
把整个88角点投影回图像，与实测角点比较。
采集画面中的PnP拟合误差只衡量单张图像角点拟合质量，两者含义不同。

若有独立测量、且原点/轴方向与本棋盘格约定一致的 T_world_board 真值.npy，
可在评估命令追加 --ground-truth /绝对路径/T_world_board.npy，计算相对该真值的误差。
真值不能用同一手眼标定结果反推，否则不独立。
